# 粮食产量模型可视化演示页

一个**单文件网页**，用 XGBoost、SHAP、LSTM 三个模型展示同一份数据上的预测与解释结果。
双击 `web/index.html` 即可打开，**不需要联网、不需要装任何依赖**。

---

## 一、页面包含什么

| 页签 | 内容 |
|---|---|
| 项目概览 | 数据规模、目标变量、7 个特征、三个模型的口径说明 |
| XGBoost | 特征重要性、留一省 R²（分省）、预测值与实际值散点、分省明细表 |
| SHAP 解释 | 全局平均 \|SHAP\|、案例样本的逐特征贡献、气温与降水的边际影响曲线 |
| LSTM | 训练损失曲线、与 XGBoost 的留一省中位 R² 对比 |
| 交互预测 | 7 个滑块实时调整输入，页面内嵌树模型当场推理，输出预测产量 |

## 二、数据与模型口径

- **数据**：粮食主产区地级市面板，1 685 条建模样本，12 个主产省、152 个地级市，2000–2021 年
- **目标变量**：粮食产量（万吨）取对数
- **特征（7 个）**：播种面积（对数）、常用耕地面积、年均气温、年降水量、年均露点温度、纬度、经度
- **XGBoost**：300 棵树、最大深度 5、学习率 0.05、subsample 0.8、colsample 0.8
- **留一省协议**：每次把一整个省留作测试集，衡量跨省外推能力；每折至少 30 个测试样本

主要结果：

| 协议 | XGBoost | LSTM |
|---|---|---|
| 随机 8:2 | 0.962 | — |
| 留一省（中位） | 0.754 | 0.751 |

## 三、三个模型分别做了什么

**XGBoost** 负责预测与归因。梯度提升树在表格数据上表现稳定，特征重要性显示预测主要依赖
播种面积与耕地面积。

**SHAP** 负责解释单条预测。用的是 XGBoost 内置的 TreeSHAP（精确解，不是近似采样），
把每条预测拆成「基线值 + 各特征贡献」，案例样本可在页面上看到逐项贡献。

**LSTM** 负责时序视角。输入同一城市连续三年（t−2、t−1、t）的特征，预测第 t 年的产量。
由于本机无法安装深度学习框架，这一部分用 NumPy 手写了单层 LSTM（8 个隐单元）加线性输出层，
用 Adam 优化、全批量 BPTT 训练。梯度已用有限差分校验，最大相对误差 5.2e−7。

## 四、交互预测是怎么实现的

页面没有调用后端，而是把训练好的 300 棵树导出成 JSON 内嵌进 HTML，用一段 JavaScript
遍历树结构求叶子和。关键细节是**阈值与取值都用 `Math.fround` 转成 float32 再比较**，
与 XGBoost 内部的判定一致，因此浏览器结果与 Python 端完全吻合（实测最大偏差 2e−6）。

## 五、如何重新生成

```bash
# 1. 训练 XGBoost、计算 SHAP、导出树模型  →  web/data.json
python scripts/build_web_data.py

# 2. 训练 NumPy LSTM（留一省）              →  web/lstm.json
python scripts/train_lstm_city.py

# 3. 渲染图表并组装页面                     →  web/index.html
python scripts/build_demo_page.py
```

依赖：`numpy`、`pandas`、`scikit-learn`、`xgboost`、`matplotlib`。
三个脚本里的输入路径指向 `D:\DC\deliverables\city-grain-data\主产区市级面板_2000_2024.csv`，
换目录时改脚本开头的 `PANEL` 常量即可。

## 六、需要知道的三点局限

**模型主要学到的是规模关系，不是气候信号。** 特征重要性里耕地面积与播种面积占了大头；
把这些规模变量去掉、只用气候变量做留一省，中位 R² 会掉到 0 附近甚至为负。
所以页面上呈现的高 R² 应理解为「用地面积能跨省推产量规模」，而不是「气候能预测产量」。

**LSTM 是自实现版本。** 单层 8 隐单元远小于工业级配置，但梯度经过校验、协议与 XGBoost 一致，
作为演示足够；如果要用在论文里，建议换成框架实现并做超参搜索。

**样本里有约 45% 是县级加总校准估算值**（在源数据文件里用「产量数据来源」列标注）。
演示页为了样本量把它们纳入训练，若用于正式结论，建议只用官方值子集重跑。
