# M08 数据整备

> 一句话：把「别人的表」变成「能复现的面板」，并在同一屏上告诉用户哪里会出错。

## 1. 为什么加这个模块

项目对外的定位是「科研与教学工具」，但此前只服务自己那套面板：数据在仓库里，别人拿不走。
M08 把这件事翻过来——**用户带自己的数据来**，系统负责对齐口径、统一单位、检查质量、拼上气候，
最后交出四样东西：清洗后的面板、质检报告、复现脚本、明确的边界说明。

真正的差异点不在「支持上传」，而在**它知道哪些地方会错**。规则全部来自做 14,388 条县级面板
时踩过的坑：公顷/千公顷混用、重名县、市辖区合计行、总产与单产互相矛盾、年份缺口、2023 无真值。

一句话讲法：**跨学科合作最容易翻车的地方在口径交接，不在算法。**

## 2. 三条硬边界

1. **不写主库。** 上传数据只落在 `backend/data/ingest/<sid>/`，24 小时自动清理；
   绝不写入 `county.db` / `grain.db`，避免污染 M01/M07 的数字。
2. **不出风险结论。** 内置模型只在中国 10 个主产省训练，别国数据只做清洗与气候拼接。
3. **不做外推。** 气候只认本地栅格覆盖的年份，缺年份就留空并在报告里写明，不插值。

## 3. 两条路径

| | 中国模式 | 国外模式 |
|---|---|---|
| 统计表 | 必须上传 | 必须上传 |
| 地理数据 | 不用传，用内置 `county_meta`（1,199 县） | 必须传 GeoJSON（Polygon / MultiPolygon） |
| 气候 | 直接查 `county.db` 的县年气候（2012–2023） | 按单元中心点读本地 TerraClimate 4.6 km 栅格 |
| 匹配键 | 区划代码 → 省+县 → 县名唯一 | GeoJSON 的 `name` / `code` |
| 生长季 | 4–9 月 | 北半球 4–9 月 / 南半球 10–次年 3 月 |

## 4. 四步界面

| 步骤 | 内容 | 关键设计 |
|---|---|---|
| 1 上传 | 模式切换 + 两个拖拽区 + 模板下载 | 中国模式把地理区置灰，直接告诉用户「不需要」 |
| 2 映射 | 8 个标准字段逐个下拉 + 单位选择 | 单位单独一行，默认值与建议并列，防止盲过 |
| 3 质检 | 四个指标卡 + 阻断/警告/提示三级列表 | 每条给「命中行数 + 示例 + 建议动作」 |
| 4 导出 | 20 行预览 + 三个导出按钮 | 明确写「只证明表可用，不证明结论」 |

## 5. 质检规则

| 级别 | 规则 | 判据 |
|---|---|---|
| 阻断 | 年份缺失或越界 | 空值或不在 1950–2030 |
| 阻断 | 同地区同年重复 | 地区键 + 年份重复 |
| 阻断 | 地区匹配率 < 50% | 中国模式下对不上内置县 |
| 警告 | 单位疑似选错 | 列中位数与所选单位量级不符 |
| 警告 | 总产 / 面积 / 单产矛盾 | `总产 ÷ (面积×1000)` 与单产相差 > 5% |
| 警告 | 播种面积缺失 > 30% | 缺面积就无法剥离规模 |
| 警告 | 年际跳变 > 5 倍 | **按地区分组**比较相邻年份，不能全表排序 |
| 警告 | 气候回填不完整 | 覆盖率 < 100% |
| 提示 | 市辖区合计行 | 地区名含「市辖区」 |
| 提示 | 年份超出气候窗口 | 不在 2012–2023 |
| 提示 | 2023 无产量真值 | 中国模式专有 |

## 6. 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/api/ingest/sessions` | 上传（multipart：`stats` 必填、`geo` 国外模式必填） |
| POST | `/api/ingest/sessions/<sid>/run` | 按映射与单位执行清洗 |
| GET | `/api/ingest/sessions/<sid>` | 会话元信息与上次结果 |
| GET | `/api/ingest/sessions/<sid>/export/<kind>` | `csv` / `report` / `script` |

会话状态全部落盘（`meta.json`），不放内存——gunicorn 多 worker 下内存态会丢。

## 7. 实现要点与踩过的坑

- **单位折算**：吨/万吨/千克、千公顷/公顷/亩/万亩、吨每公顷/公斤每公顷/公斤每亩/斤每亩。
  系数写在一张表里，前后端共用同一份选项。
- **匹配优先级**：区划代码 → 省+县 → 县名唯一；重名县只给提示，绝不猜。
- **netCDF4 外积坑**：`v[:, jj, ii]` 是每个 j 配每个 i，不是点对点。
  改成按 30° 瓦片读窗口，再在窗口内取点。
- **TerraClimate 纬度降序**：90 → -90，索引前必须翻转。
- **`itertuples()` 会改下划线列名**：`_prov` 被改成位置名，改用 `prov_norm`。
- **`pd.NA` 不能直接做布尔判断**：`if code_raw:` 会抛 `boolean value of NA is ambiguous`。
- **未匹配判定用 `match_method`**：国外模式的单元没有区划代码，用 `matched_code.isna()`
  会把「全部匹配成功」误报成「全部未匹配」。
- **年际跳变必须分组**：全表按年份排序会把不同县的相邻行串在一起，制造假阳性。

## 8. 验证记录（2026-10-20）

- `pytest backend/tests/test_ingest.py`：8 条全过（映射/单位/重复/GeoJSON 质心/端到端/扩展名/国外必填/误报回归）。
- 浏览器实测（Playwright + 系统 Chrome）：中国模式四步走通，7 行样例输出 32 列；
  国外模式 3 单元 × 2 年，5 秒完成，匹配与气候覆盖均 100%。
- 全量后端测试：173 passed / 1 failed。失败项是 `test_provinces_item_has_all_11_features`，
  原因是 `/api/provinces` 走 `grain.db` 后字段名漂移（`province`/`flood_r` 取代
  `name`/`flood`），与 M08 无关，属于既有数据契约问题。

## 9. 已知边界与后续

- 气候窗口只有 2012–2023；更早年份需要用户自带气候表。
- 国外模式只取多边形**质心**，不代表面平均；复杂地形会有偏差。
- 国外模式暂不拼 SPEI（本地 `spei03.nc` 是全球 0.5°，可以接，但要单独做格点对齐）。
- 上传上限 10 MB / 20 万行；超大表需要走后台任务队列，当前不做。
