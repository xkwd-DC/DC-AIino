# 县级站点层（M07 县级风险地图）

> 建立时间：2026-10-15 ｜ 目的：把已跑完的县级实验（v6/v7）**接进站点**，让系统不再只跑省级 v3 面板。
> 一句话：站点新增 M07，服务 10 主产省 1,199 县 × 12 年 = 14,388 个县年的**纯气候归因**，
> 省级 M01–M04 一行未动（两套口径并行，互不覆盖）。

---

## 1. 为什么要加这一层

站点此前的读路径只有一条：`backend/data/grain.db` ← `paper_panel_v3.parquet`（31 省 × 13 年 = 403 行）。
而 2026 年 6–9 月跑出来的县级实验（v6/v7/v8）只活在 `scripts/data/` 与 `reports/` 里，没有对外可查的入口。
造成的三个问题：

1. 对外演示的粒度停在省级，而省级的 leave-province-out 中位 R² = **−16.83**，评委必然追问"为什么不做到县"；
2. 县级的可迁移结果（CLIMG LCO **+0.4489**）无法在系统里被看到，只能引用报告；
3. 「空间粒度下移」在各版材料里一直被写成"未来展望"。

## 2. 数据层

| 项 | 内容 |
|---|---|
| 来源面板 | `data/interim/paper_panel_v7_prediction.parquet`（14,388 × 53） |
| 覆盖 | 10 主产省 × 1,199 县 × 2012–2023 |
| 气候齐备 | 14,352 行（99.7%）；有产量真值 10,426 行（72.5%），两者交集 10,407 行 |
| 落库 | `backend/data/county.db`（**与 grain.db 并行**，服务端 read-only 打开） |

`county.db` 的表：

| 表 | 行数 | 用途 |
|---|---:|---|
| `county_meta` | 1,199 | 县代码 / 名称 / 城市 / 省份 / 经纬度 / `map_key` / `on_map` |
| `county_panel` | 14,388 | 目标 + 16 维气候 + 统计与遥感列（中文列名已映射成语义列名） |
| `county_model_out` | 14,352 | 预测 / SHAP 气候贡献 / 气候异常 / 风险等级 / 单元类型 |
| `feature_direction` | 16 | 各气候特征训练期↔测试期的方向一致性 |
| `county_standard` | ~250 | 官方协议数字（v6_12 / v6_13 的报告 CSV 原样灌入） |

> **列名坑**：v7 面板前 17 列是中文列名（GBK 遗留）。ETL 用显式映射表转换，**不按位置索引**。
> **地图键**：天地图县级边界有重名（桥西区/新华区/郊区/鼓楼区/市中区），ETL 给重名县加省份前缀，
> 面板的 `map_key` 与前端 geojson 的 `properties.name` 由同一函数生成，保证按名着色零错配。

## 3. 模型层：为什么只吃气候

`log(粮食总产量)` 的方差约 **92% 由播种面积（规模）解释**（与 log 面积相关 0.9597）。
若把规模放回特征，LCO R² 从 0.4489 抬到 0.6465 —— 那是规模在解释规模。
所以站点县级层的部署模型是 **CLIMG 16 维纯气候**，排除项写死在 `v9_02` 与模型卡里：

- 排除 `log_sown`（播种面积/规模）；
- 排除省-年共享常量（遥感 NDVI&LST、化肥、灌溉、成灾面积、耕地占比）。

官方可报的迁移能力（5 种子，来自 `reports/v6_12_*.csv`，站点**不重算**）：

| 配置 | 维数 | LCO（跨县） | 时间外推（≤2019→2020-22） |
|---|---:|---|---|
| CLIM3 纯年均气候 | 3 | +0.2600 ± 0.0044 | +0.2216 ± 0.0024 |
| CLIM5 + 县级 SPEI | 5 | +0.3241 ± 0.0060 | +0.2366 ± 0.0044 |
| **CLIMG + 生长季/极端指数** | **16** | **+0.4489 ± 0.0065** | **+0.3644 ± 0.0044** |
| CLIMG+播种面积（对照，不对外报） | 17 | +0.6465 ± 0.0046 | +0.4530 ± 0.0050 |
| 单产口径 CLIMG | 16 | +0.5208 ± 0.0065（只报 LCO） | — |

配套：permutation null（CLIMG 真实 +0.4489 vs null −0.0157，真实 100% 超 null）、
bootstrap 增益（CLIM3→CLIMG Δ=+0.1888，95%CI [+0.1241, +0.1848]，P(Δ≤0)=0.000）、
seed42 本机复现与报告逐位一致（LCO 0.4580 / 时间 0.3609 / RMSE 1.0239）。

产物：`backend/models/county_climg_xgb.pkl`、`county_climg_features.json`、
`county_climg_card.md`（模型卡，含方向稳定性、边界与不可越界表述）。

## 4. 两个指数不要混用（这一层最容易讲错的地方）

| 指数 | 定义 | 能读 | 不能读 |
|---|---|---|---|
| `clim_contrib` / `contrib_pct` | Σ SHAP，气候对该县该年 log 产量的模型边际贡献 | 该县的气候条件**画像**（跨县可比） | 不能当"今年风险"：县际结构差异混在里面，LCO 口径下气候特征还会替省份尺度背书 |
| `clim_anomaly` / `risk_pct` / `risk_level` | `clim_contrib` 减该县历年均值 | "今年该县气候相对自身常态偏差多大"，逐年可比、可做时间轴 | 不回答"哪个县的绝对气候条件更差" |

地图与风险等级默认走 `clim_anomaly`；`clim_contrib` 只在明细卡里作气候画像展示。
两者都由 `v9_02` 预计算落库，**请求期不算 SHAP**。

## 5. 覆盖与口径标记

- **单元类型**：县域统计年鉴把市辖区一并列出，其中城市核心区年粮食产量仅数十吨（如成都青羊区 33 吨），
  与主产县不在同一口径上，模型在这些极端单元上会外推。站点用 `unit_type` 标出
  `farm`（该县多年中位产量 ≥ 1 万吨）/ `urban` / `unknown`，前端可切「仅主产单元」（999 县）。
  单元类型是**县**的属性而非县年的属性 —— 否则 2023 年（面板无产量真值）会把全部县打成 unknown。
- **2023 年无产量真值**：县域统计年鉴 2024 卷未出版，2023 年 1,196 个县年**全部没有 truth**。
  该年的气候贡献是纯外推。前端因此：
  1. 默认年落在**最新有真值的年**（2022），而不是面板末年；
  2. 逐年披露覆盖（`meta/summary.year_coverage`）；
  3. 选中无真值年份时明细卡显式挂警示条。

## 6. 接口

| 端点 | 说明 |
|---|---|
| `GET /api/counties?year=&unit=all\|farm&province=` | 某年县级快照（缺 year 给最新年） |
| `GET /api/counties/meta/summary` | 覆盖率、逐年 truth、省份分布、元信息、指标定义 |
| `GET /api/counties/meta/standard` | 空间粒度递进 + null + bootstrap + 规模诊断（前端**不写死任何数字**） |
| `GET /api/counties/<code>/history` | 单县 2012–2023 轨迹 |
| `GET /api/counties/<code>/attribution?year=` | 单县单年 16 维气候边际贡献（按绝对值排序） |

实现：`backend/services/county_repo.py`（read-only 连接 + 显式异常）、`backend/api/county_api.py`（Blueprint，
与 `/api/provinces` 同档 500/hour 限流）。`county.db` 缺失时整组端点返 503，**省级模块不受影响**。

## 7. 前端

新模块 M07 `/county-risk`，刻意拆成"容器 + 三个纯组件"，避免又出现一个 1000 行的单文件：

| 文件 | 职责 |
|---|---|
| `frontend/src/views/CountyRiskMap.vue` | 取数与编排（年份 / 单元口径 / 省份筛选、选中县联动） |
| `frontend/src/components/county/CountyMap.vue` | ECharts 县域 choropleth（1,248 面 / 1,169 面有数据） |
| `frontend/src/components/county/CountyDetail.vue` | 选中县明细：逐年气候异常柱状图 + 当年归因 Top 6 + 方向稳定性标记 |
| `frontend/src/components/county/GranularityLadder.vue` | 口径与迁移体检屏（省级↔县级并排 + null + bootstrap + 规模诊断） |
| `frontend/public/maps/counties_10provinces.json` | 10 主产省县级边界（天地图 GS(2024)0650），坐标降精度、`name` 重写为唯一键 |

无障碍：地图 `role="img"` + 文字替代（高风险县 Top 10 是**可键盘操作的按钮列表**，也是地图的 text alternative）；
色阶不只靠颜色（等级带 L1–L5 文本与计数）；宽表用可聚焦的横向滚动 region 兜住（窄屏 390px 无横向溢出）。

## 8. 重建与部署

```bash
# 1) 县级面板 → county.db + 前端地图资产（约 3 s）
python scripts/data/v9_01_build_county_site_db.py

# 2) 训练部署模型 + 预计算 SHAP + 灌入官方协议数字（约 15 s）
python scripts/data/v9_02_train_county_climg.py

# 3) 前端构建（dist 含 /maps/counties_10provinces.json）
cd frontend && npm run build
```

- `backend/data/county.db` 与 `frontend/public/maps/counties_10provinces.json` 都在 `.gitignore` 里（可重建）；
  模型产物 `backend/models/county_climg_*` 走白名单入仓。
- **部署注意**：GCP 那台机器要跑一次上面两条 ETL，否则 `county.db` 不存在 → M07 整页返 503（省级不受影响）。

## 9. 这一层**不能**说的话

- 不主张"县级气候能预测产量水平"：目标仍是总产量口径，且已剥离规模；
- 不主张"2023 年风险已被验证"：该年无真值，是外推；
- 不把 `clim_contrib` 当"当年风险"读（见 §4）；
- 不把县级 R² 与省级 0.907 放在同一句话里比较：协议、目标、特征集都不同。
