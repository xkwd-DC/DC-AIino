# CMDC 日值 → 10 主产省省级年度极端指数（1979–2023）

## 结论

本地那三个躺了很久、全仓库零引用的 CMDC zip 已经接上了：气温 + 降水两个包（第三个是 Africa 包，用不上）
跑出了 **10 主产省 × 45 年（1979–2023）** 的省级年度极端指数面板，450 行、14 列，无缺失。

这一步补的是两个短板：

1. **唯一一路逐日观测**进了系统。此前所有气候特征都来自 TerraClimate / NASA POWER / SPEI 这类再分析或
   网格产品；现在有了真实台站的日值聚合。
2. **检验窗从 12 年拉到 45 年**。面板的县级气候只有 2012–2023，而极端指数的气候基线可以是 1979–2023，
   2012–2023 的异常值因此可以放在 4 倍长的基线上标准化（`reports/cmdc_province_anomaly_z45.csv`）。

**但要说清一件事**：论文 §2.1 与软著写的是「气象观测来自 CMDC 省域逐日监测数据」，实际能落地的是
**每省 7–24 个国家级台站**（10 省合计 125–130 站），不是「省域逐日监测」那种网格化观测。
这句话要么改口径，要么在方法里交代站网密度。

## 数据源与两个读取坑

| 包 | 内容 | 大小 |
|---|---|---|
| `SURF_GLB_TEM_DAY_PROD_Asia_YYYY.zip` | 日平均气温 `V12001`，45 年 | 296.6 MB |
| `SURF_GLB_PRE_DAY_V2_Asia_YYYY.zip` | 日累计降水量 `V13011`，45 年 | 233.3 MB |
| `SURF_GLB_PRE_DAY_V2_Africa_YYYY.zip` | 非洲包，**与本任务无关** | 41.7 MB |

1. **两包列序不同**：气温是 `V05001`(纬) → `V06001`(经)，降水是 `V06001`(经) → `V05001`(纬)。
   脚本一律按列名取列，按位置取会在降水上把经纬度对调。
2. 外层 zip → 年内层 zip → 单个约 28 MB 的 GBK 编码 TSV。外层文件名是 UUID，脚本靠**内含成员名**识别包，
   不依赖文件名。

## 指数定义

| 列名 | 含义 | 备注 |
|---|---|---|
| `tmean_annual` | 年平均气温 (°C) | 站间均值 → 省值 |
| `gs_tmean` | 生长季（4–9 月）平均气温 | 口径沿用 `v6_09_build_seasonal_features.py` 的 `GS=[4..9]` |
| `gdd10` | 生长季积温，基温 10 °C | 逐日 `max(T−10, 0)` 累加 |
| `days_tmean_ge30` | 日平均气温 ≥ 30 °C 日数 | ⚠️ **自定义阈值，非标准 ETCCDI 指数**，引用时必须标注 |
| `prcptot_mm` | 年降水总量 (mm) | |
| `r1mm_days` | 日降水 ≥ 1.0 mm 日数 | |
| `r25mm_days` / `r50mm_days` | 日降水 ≥ 25 / 50 mm 日数 | |
| `cdd_days` | 最长连续无雨日 | 日降水 < 1.0 mm 记旱日，缺测不算旱日且打断连续段 |

**算不出来的**：本地 `V12001` 只有日平均气温，**没有日最高/最低气温**，所以 TX35、TX90p、DTR（日较差）
这组标准 ETCCDI 温度指数无法计算。这轮不另行申请数据。

## 站点覆盖

站 → 省归属用 `data/raw/gis_province/counties_10provinces_GS2024.geojson` 点在多边形（省级面投影到米制后外扩
2 km 补缝），**不用「最近省会」**。亚洲站规模随年份从 1,200（1979）涨到峰值 2,293（2022），
其中落入 10 主产省的为 **125（1979）~ 129（2003）站，全期均值 127.4 站**——站数本身稳定，
变的主要是包里的境外站。

## 质量核查

- **行数与日期**：每年气温 ~59 万行、降水 ~55 万行；日期覆盖完整年，闰年为 366 天。
- **值域**：全亚洲日平均气温 −44.3 ~ 44.3 °C、日降水最大值出现在境外站；10 省子集单日降水最大
  165.9（1979）/ 244.9（2000）/ 232.4（2019）/ 300.0（2022）/ 285.0（2023）mm，量级正常。
- **质控码是个坑**：`Q13011` 与数值大小**完全共线**（Q=0 的最大值只有 9.0 mm，Q=1/2 全在 9.5 mm 以上），
  这不可能是真正的质控语义。若按「只留 Q=0」过滤，福建某站年降水会从 1529.8 mm 塌到 219.3 mm —— 与实况相差 7 倍。
  **结论：不能按 Q 过滤**，本管线保留全部记录。
- **物理阈值兜底**：对 `|prec| > 400 mm` 与 `|tmean| > 60 °C` 做裁剪。越界记录全是境外站的坏值
  （例如巴基斯坦站 `PKM00041785` 报出 −120 °C，且其经纬度也不自洽），经逐条核验，
  **10 主产省内受影响记录为 0**，即本面板的裁剪没有误伤。

## 已知局限

1. **站网稀疏**：每省 7–24 站，且是国家级基准站。用它代表「省域」极端气候，在站点稀疏省（江苏、安徽）
   会有明显代表性误差。这是数据本身的天花板，不是聚合方法的问题。
2. **无日最高/最低温** → 标准 ETCCDI 温度指数缺失，只能用自定义的 `days_tmean_ge30` 顶上，论文里必须标注。
3. **省级均值未做面积加权**：各指数是站间算术平均。禾本科作物主产区与站网分布不重合时会有偏。
   如果需要，可按县面积给站赋权重算（需要站-县映射）。
4. **长窗的产量侧接不上**：本地省级粮食产量只有 2011–2025（`分省年度粮食产量数据.xlsx`），
   1979 起的产量序列没有，所以 45 年窗口目前只能用于**气候侧**的趋势与基线，
   做不了「45 年产量-极端指数」的长窗回归。这一条和 A1 卡在同一个数据缺口上。
5. `n_station_days_temp` 与 `n_station_days_prec` 在部分省不等（气温站比降水站多），
   同省气温与降水指数所用的站集并非完全一致。
